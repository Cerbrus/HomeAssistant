# CLAUDE.md

## Project

- This is a Home Assistant configuration repository running on a **Raspberry Pi 4**
- **Reverse proxy**: Nginx Proxy Manager with Let's Encrypt SSL
- **Media stack**: Plex, Radarr, Sonarr, Bazarr, Prowlarr
- The setup is described in [`docs/`](docs/README.md); decisions and their reasons are in [`docs/adr/`](docs/adr/README.md). Read the relevant document before changing something, and check the ADRs before "fixing" behaviour that looks wrong.

## Documentation and ADRs

These rules apply to every change to the setup, whether it is made in this repository or on the running instance (HA-MCP, the HA UI, an app's settings).

- **Update the docs in the same change.** A change to automations, scripts, helpers, integrations, apps, devices, areas, dashboards, the sidebar, network access or deployment updates the matching file under `docs/`. Most of the setup lives in UI-managed state that is not in git, so the docs are its only record here.
- **Write an ADR when a choice is made.** When a change settles a choice between alternatives, establishes a convention, or leaves something odd in place on purpose, add `docs/adr/NNNN-short-title.md` from `docs/adr/template.md` with the next free number and add it to the index in `docs/adr/README.md`. The criteria are in that README. When in doubt whether a change needs an ADR, ask.
- **Never rewrite an accepted decision.** A changed decision gets a new ADR; the old one's status becomes `Superseded by ADR-NNNN`. Confirming or correcting the rationale of a backfilled ADR is allowed: set its origin to `Backfilled, rationale confirmed`.
- **Ask for the reason, do not invent it.** An ADR records why. When the reason for a decision is not stated, ask before writing it down.
- **Export the dashboards after a dashboard change.** Run `python tools/export_dashboards.py <user@pi>` (SSH target from the private homelab note) and include `dashboards/` in the same change. Never hand-edit the files in `dashboards/`.
- **Ask before adding a Marketplace card or integration.** Only what is in use stays installed ([ADR-0019](docs/adr/0019-lean-marketplace.md)). When a dashboard or feature would need a card or integration that is not installed, any one, ask for confirmation first; do not download it unasked and do not design around it silently.
- **Keep `docs/open-items.md` honest.** Delete an item when it is handled: no "handled" section, no strike-through, no dated note. Add one when a loose end is found and left.
- **The repository is public.** No LAN or public IP addresses, MAC addresses, port forwards, modem settings, zone coordinates, account names, calendar names or secrets in docs, ADRs or commit messages. Host names under `cerbrus.nl`, entity ids and device names are fine. Network detail belongs in the private homelab note. The same goes for security weaknesses and accepted risks (default or weak credentials, unpatched or exposed services): never in docs, ADRs, open items, dashboards or commit messages.

## www Directory Structure

- `www/icons/` - Dashboard icons (media stack logos, mascot)
- `www/sidebar-organizer.yaml` - Sidebar grouping for the Sidebar Organizer module

## Other directories

- `dashboards/` - Redacted clone of the UI-managed dashboards, generated by `tools/export_dashboards.py`
- `tools/` - Maintenance scripts run from the PC, not used by Home Assistant
